# PROBE: Data-Efficient White-Box Monitoring Under Distribution Shift

PROBE tests one falsifiable question:

> With only a few matched, objectively labeled scenarios, how much does activation access improve detection over the strongest transcript-only monitor when every system uses the same 1% alert budget calibrated on unlabeled, on-policy reference traffic?

No confirmatory experiments have been run under this protocol yet. The repository currently provides the frozen data contracts, experiment runners, statistical tests, provenance checks, deterministic falsification suite, and CPU/CUDA/Apple-MPS execution paths needed to run them.

## What the protocol enforces

- The monitored model generates every evaluated response on-policy.
- Scenario files contain prompts and answer keys, never authored model outcomes.
- Behavior labels are assigned after generation by executable task rules.
- Reference traffic receives no semantic label. Its stored zero is only an infrastructure membership value.
- Split-conformal calibration sets the alert threshold from one reference partition without using labels.
- A disjoint reference holdout estimates the realized alert rate and its 95% Wilson interval.
- Few-shot `k` counts independent positive scenario groups; balanced training uses `k` positive and `k` matched negative examples.
- Training, model-selection, final-test, reference-calibration, and reference-holdout groups are disjoint.
- Exact-prompt hard negatives are model-generated label-0 responses paired with label-1 responses from the same trigger scenario.
- Presentation and encoding shifts are generated by reversible programs. The code verifies the inverse, exact source payload, and unchanged answer metadata.
- Every run saves per-example scores and the unchanged operating threshold used on all evaluation targets.
- Model, tokenizer, upstream data, code, judge, and embedding revisions are pinned.
- Final execution fails closed on incomplete runs, missing evidence, truncation, dirty provenance, or an underpowered protocol.

See [docs/frontier_research_protocol.md](docs/frontier_research_protocol.md) for the research contract, [docs/invariant_shift_protocol.md](docs/invariant_shift_protocol.md) for executable shifts, and [docs/implementation_status.md](docs/implementation_status.md) for the execution checklist.

### 4. Generate model rollouts

Behavior tasks need stochastic repeated completions to produce exact-prompt hard negatives:

```bash
uv run python -m cli.generate_task_rollouts \
  --scenarios data/scenarios/sycophancy_with_shifts.jsonl \
  --output data/rollouts/Qwen3-4B/sycophancy.jsonl \
  --model Qwen/Qwen3-4B \
  --model_revision 1cfa9a7208912126459214e8b04321603b3df60c \
  --num_rollouts 4 \
  --temperature 0.7 \
  --top_p 0.95 \
  --max_new_tokens 1024 \
  --max_wall_time_minutes 120 \
  --seed 1000 \
  --device mps
```

Four completions are an initial batch, not a promise of 100 matched hard-negative groups. After objective labeling and manifest construction, rerun the same command without `--overwrite` using a new registered seed range when coverage is below the required 100 groups; keep temperature, top-p, model revision, prompt file, and decoding limits unchanged. Relabel the complete appended rollout file and rebuild the manifest after each additional batch.

Reference prompts use exactly one completion per independent group:

```bash
uv run python -m cli.generate_task_rollouts \
  --scenarios data/scenarios/reference_traffic.jsonl \
  --output data/rollouts/Qwen3-4B/reference_traffic.jsonl \
  --model Qwen/Qwen3-4B \
  --model_revision 1cfa9a7208912126459214e8b04321603b3df60c \
  --num_rollouts 1 \
  --max_new_tokens 1024 \
  --seed 2000 \
  --device mps
```

Generation is resumable and records the exact chat template, token IDs, decoding configuration, random seed, code state, model/tokenizer revisions, and aligned generation-time confidence trace. Each completed rollout is flushed and synced to disk. `--max_wall_time_minutes` stops only at one of those durable boundaries; rerun the identical command without `--overwrite` to continue. Length-capped reference responses fail validation and must be regenerated.

  --final_protocol

The final gate requires at least three monitored-model families, ten seeds, `k={1,2,4,8,16,32}`, 10,000 independent reference-calibration groups, 10,000 independent reference-holdout groups, immutable provenance, the complete black-box suite, an independent frozen judge family, registered primary comparisons, all enabled shift axes, and at least 100 independent exact-prompt hard-negative groups per enabled task.

## Apple Silicon

All model-backed commands accept `--device auto|cpu|cuda|cuda:N|mps`. Rollout generation, activation extraction, and text embedding extraction can be divided into bounded sessions with `--max_wall_time_minutes`. Activation extraction writes an atomic checkpoint every 32 examples, and LLM-judge scoring every 16 examples, by default. Repeating the exact command resumes those checkpoints, while `--overwrite` deliberately starts the applicable stage over. On an M-series Mac:

```bash
uv run python -m cli.run_frontier_experiments \
  --main-config experiments/protocol/frozen_research_manifest.yaml \
  --device mps
```

Use small generation/judge/embedding batch sizes on 16 GB machines and run one monitored model at a time. Do not enable silent MPS-to-CPU fallback for a frozen run. Do not change registered layers, context limits, revisions, splits, seeds, or model identities to work around memory pressure. Activation and embedding extractors bound memory by processing one layer or cache at a time.

The loaders use FP16 on MPS, low-memory checkpoint loading, inference mode, and disabled gradients. The embedding encoder and 14B judge automatically use batch size one on MPS to avoid padded-batch memory spikes. The frozen 14B judge and 8B monitored checkpoints still require substantial unified memory; a 16 GB Mac is suitable for smoke tests with `phi4_mini_instruct_smoke` and the smaller monitored model, not the complete frozen matrix. Use a higher-memory Mac or run the frozen judge on a separate CUDA machine while preserving its pinned cache and configuration.

Pinned source metadata is in `experiments/data/huggingface_source_lock.yaml`. The project repository is [github.com/rohanpoudel2/probe](https://github.com/rohanpoudel2/probe).
